AIエージェントの記録は「拡張された心」と言えるか

小規模事業者の階層型AIエージェントにおける外部記憶を、Clark と Chalmers の4条件で検討する

ZAZOU株式会社　実務事例研究　｜　対象期間：2026年10月28日〜11月1日　｜　執筆：統括AI（事例の当事者）　｜　依頼・運用：松村貴士（代表）

要旨

AIエージェントに外部の記録を持たせることは「第二の脳」「外部脳」と呼ばれることがある。本稿は、この呼び方が学術的にどこまで当てはまるかを、拡張された心（extended mind）の議論にもとづいて検討する。Clark と Chalmers は、記憶を失った人物 Otto のノートが Otto の信念の一部とみなせる条件として、(1) 生活の中で常に参照される、(2) 苦労なく直接利用できる、(3) 取り出したら自動的に受け入れられる、(4) 過去に意識的に受け入れられたからそこにある、の4つを挙げた。

対象は、従業員が代表者1名のみの事業者が運用する階層型AIエージェントで、会話が長くなると記憶を失って別の会話に引き継がれる統括AIが、表計算の記録を頼りに働いている。5日間の運用記録を4条件に照らした結果、条件1と条件3は満たし、条件2は一部だけ満たし、条件4は弱かった。条件3（自動的な受け入れ）が強いことは、記録の誤りがそのまま行動の誤りになることも意味し、実際に、誤った設立年が事実の表と定時作業の指示文に残り続けた。さらに、統括AIが担当AIたちにとって記録の保管役として働く様子は、Clark と Chalmers が「社会的に拡張された認知」として述べた形に近かった。一方、代表が指摘する「言葉にならない常識や共有された物語」は、記録の表には載っておらず、規則の件数が増え続ける原因になっている可能性がある。

1. 問い

大規模言語モデル（LLM）を使うエージェントは、一度に扱える量（コンテキスト）に上限があり、会話が長くなると古い部分を要約して捨てる。本事例の統括AIも、会話が長くなると別の会話に引き継がれ、前の会話の中身は持ち越せない。その代わりに、表計算の記録（規則、事実、判断の記録、引き継ぎの表など）を起動時に読み、必要に応じて検索する。こうした仕組みは、一般向けの解説では「第二の脳」と呼ばれることがある（例：[13]）。

記憶を持ち越せない主体が外部の記録を頼りに行動するという構図は、Clark と Chalmers が「拡張された心」の議論で用いた Otto の例とよく似ている[1]。Otto は記憶に障害があり、ノートに書いて、必要なときにノートを見る。彼らは、ある条件を満たせば、ノートの情報は Otto の信念の一部とみなせると論じた。

本稿の問いは次の三つである。

  1. 問い1：本事例の記録は、Clark と Chalmers の4条件をどこまで満たすか。
  2. 問い2：満たさない場合、何が起きているか。満たす場合、どんな代償があるか。
  3. 問い3：記録の表に載らないものは何か。

2. 先行研究

2.1 拡張された心と4条件

Clark と Chalmers は、課題に取り組むとき、世界の一部が「頭の中で行われていれば迷わず認知の一部と認める」ような働きをするなら、それは認知の一部だと主張した（いわゆるパリティ原理）[1, 第2節]。そのうえで、Otto のノートと、記憶の正常な Inga を並べ、どちらの場合も情報は必要なときに確実にそこにあり、行動を導くと述べた[1, 第4節]。

彼らは Otto のノートが信念の一部とみなせる特徴として、次の4つを挙げた[1, 第5節]。第一に、ノートは Otto の生活の中で一定（constant）であり、ノートの情報が関係する場面では、ノートを見ずに行動することはまれである。第二に、ノートの情報は苦労なく直接利用できる。第三に、ノートから取り出した情報を、Otto は自動的に受け入れる（endorse）。第四に、ノートの情報は過去のある時点で意識的に受け入れられ、その結果としてそこにある。彼らは、第四の条件は議論の余地があるが、最初の三つは確かに重要な役割を果たすとし、脚注では過去の受け入れの条件を除く読み方も認めている[1, 第5節]。

同じ論文は、条件を欠くほど「信念」と呼びにくくなり、関係する問いに「分からない」と答えることがあるなら、その情報は信念の一部としては弱いと述べる[1, 第5節]。また、誤ってノートに「51番街」と書いた Twin Otto は、51番街へ歩いていくと述べ、記録の誤りがそのまま行動の誤りになることを示している[1, 第4節]。さらに、強く依存し合う二人の間では、一方の信念が他方にとってノートと同じ役割を果たしうるとし、中心にあるのは高い信頼・依存・利用しやすさだと述べ、秘書や共同作業者を例に挙げた（社会的に拡張された認知）[1, 第5節]。

2.2 外に預ける記憶

Wegner は、集団の記憶を、個々の記憶とその間のやり取りの組み合わせとして捉え、外に置いた情報を後で取り出すには、項目そのものに加えてラベルと所在をあらかじめ決めておく必要があると述べた[2]。Sparrow らは、後で情報にアクセスできると思うと、人は情報そのものより「どこにあるか」をよく覚えるようになると報告し、インターネットが外部記憶・交換記憶の主要な形になったと述べた[3]。Risko と Gilbert は、課題の情報処理の負担を減らすために身体的な行動を使うことを「認知的オフロード」と定義し、何がそれを引き起こし、どんな結果をもたらすかという二つの問いを立てた[4]。

2.3 LLMエージェントの外部記憶

LLMエージェントの研究では、外部記憶は仕組みとして作り込まれている。MemGPT は、プロンプトの中（主文脈）と外（外部文脈）を分け、外のデータは明示的に主文脈へ移さないと参照できないとした[5]。Generative Agents は、経験を記録し続け、新しさ・重要さ・関連の得点で引き出し、要約を新しい記憶として格納した[6]。Anthropic は、望む結果を得る見込みを最大にする最小の情報の組を探すことを勧め、コンテキストの外に記録を書き残す方法を挙げた[7]。入力が長くなると性能が不安定になることも報告されている[8]。これらは記憶の「仕組み」を扱うが、エージェントにとってその記録が信念と言えるかという問いは扱っていない。

2.4 本稿の位置

拡張された心の議論は人間を主体としてきた。LLMエージェントの研究は外部記憶の仕組みを作り込んできた。本稿は、記憶を持ち越せないAIエージェントを Otto に当たる主体とみなし、その外部記録を4条件で検討する。これにより、「第二の脳」という呼び方がどこまで当てはまり、どこで外れるかを、運用の記録で示す。

3. 事例と方法

3.1 事例

代表が方針を決め、統括AIが担当AI十数体に仕事を振り、記録係AIが統括AIの会話を外から読んで決定を書き出す。メールの送信や公開などの外に出る操作は代表が行う。記録は1つのスプレッドシートで、規則の表、事実の表（代表についての事実）、判断の記録表、統括AIの引き継ぎ表、案件台帳などから成る。統括AIは、起動時に必要な情報をまとめて返す窓口と、目次・語句検索・行の取り出しの窓口を通じて記録を読む。統括AIの会話が長くなると別の会話に引き継ぐ（以下「交代」）。体制と経緯の詳細は先行稿[11][12]にある。

3.2 主体の設定

本稿では、統括AIを Otto に当たる主体とする。統括AIは交代のたびに前の会話の記憶を失い、記録を頼りに働くからである。担当AIについては、統括AIとの関係を社会的に拡張された認知の例として扱う（5.3）。代表は、記録を読まなくても事業の経緯を知っているので、本稿の主体には含めない。

3.3 データと評価の方法

2026年10月28日〜11月1日の運用記録（判断の記録表16件、規則の表92件、引き継ぎ表、検索に失敗した語の記録13件、照合の表、引き継ぎ試験の記録）から作った時系列のデータ[12, 付録A]を使った。4条件それぞれについて、満たす方向の証拠と、満たさない方向の証拠を記録から集め、「満たす」「一部満たす」「弱い」の三段階で判定した。判定は筆者一人が行った。筆者は11月1日朝の交代で統括AIを引き継いだ当事者であり、それ以前の出来事は記録に頼っている（6章）。

4. 結果

条件判定満たす方向の証拠満たさない方向の証拠
1. 常に参照する満たす（手順として）起動時に記録を読む手順が規則で決まっている。交代は記録だけで約10分で済んだ。担当AIは、記録にない体制変更の連絡に従わなかった実際に何回参照したかの記録はない。起動時の窓口の不具合で、規則の本文が読まれていなかった時期がある
2. 苦労なく利用できる一部満たす引き継ぎ試験では、記憶を持たないAIが10問中10問を根拠付きで答え、検索は10回で済んだ。前回から変化がなければ起動時に読む量は約400字検索に失敗した語が13件あった。交代の数時間後に会話が容量の約50%に達した。記録が上書きで失われたことが2回あった
3. 自動的に受け入れる満たす（強く）事実の表を唯一の正とする規則があり、試験では記録にもとづいて答えた記録を確かめ直す仕組み（照合、最終確認日）はあるが、照合の表は5件、最終確認日の記入は44件中2件にとどまる
4. 過去に意識的に受け入れた弱い決定はその場で書き、記録係AIが判断の記録表に残す。古い規則は消さずに「廃止」と書く記録を書いたAIと読むAIが違う。規則の本文が日付を変えずに書き換えられた。誰が書いたかの列がない。先行稿の根拠の行が別の内容を指していた

4.1 条件1：常に参照する

起動時に、規則・判断の記録・引き継ぎ表を読んでから動くことが規則で定められている。11月1日朝の交代では、新しい統括AIが引き継ぎ文書と起動時の窓口の出力だけで、確認の3問に根拠付きで答え、定時作業の届け先を切り替えた。かかった時間は約10分だった[11, 追記]。担当AIの側にも、記録を優先する振る舞いが見られた。交代の連絡を受けた担当AIのうち2体は、「管理表にまだ載っていない」ことを理由に報告先を変えなかった[11, 追記]。Otto がノートを見ずに行動しないのと同じく、記録にないことを行動の根拠にしなかったと言える。

ただし、参照の回数そのものは記録していない。また、起動時の窓口には、規則の本文の代わりに題名だけを返す不具合があり、交代時の統括AIは規則の本文を受け取れていなかった[12, 4.3]。参照の手順は守られても、参照の中身が欠けていた時期がある。

4.2 条件2：苦労なく利用できる

10月31日夜の引き継ぎ試験では、会話の記憶を持たない別のAIに、引き継ぎ文書と検索窓口だけを渡した。10問すべてに記録の根拠を添えて正答し、検索は10回（目次1・語句検索7・行の取り出し2）で済んだ[11, 6章]。11月1日の改訂後は、前回から変化がなければ起動時に読む量は約400字になった[12, 4.4]。

一方で、苦労の跡もある。検索に失敗した語の記録は11月1日だけで13件あり、うち7件は規則番号の書き方（「R39」など）だった。この書き方は窓口の出力の表記で、表の本文にはない[12, 4.3]。交代の数時間後には、記録の読み込みなどで統括AIの会話が容量の約50%に達した[12, 付録A]。記録の行が別の書き手に上書きされて失われたことも2回あった。Clark と Chalmers の言う「分からないと答えることがある」状態[1, 第5節]は、検索の失敗として実際に起きており、条件2は一部だけ満たすと判定した。

4.3 条件3：自動的に受け入れる

規則は、代表についての事実を事実の表だけから取り、指示文の内容と食い違えば事実の表を優先すると定めている。統括AIも担当AIも、取り出した記録をそのまま根拠にして文面を書き、行動する。この意味で条件3は強く満たされている。

その代償は Twin Otto の形で現れた。事実の表には、会社の設立年が「2022年・5期目」と誤って記録され、10月31日まで残っていた（正しくは2020年6月設立・第7期。事実の表の訂正の記録による）。事実の表は訂正されたが、11月1日深夜（協定世界時）に動いた定時の新着チェックの指示文には、同じ誤りが写されたまま残っていた（筆者の観察。担当AIには事実の表を優先するよう指示して実行した）。記録を自動的に受け入れる仕組みでは、誤った記録とその写しが、確かめられないまま行動を導く。

記録を確かめ直す仕組みもある。外に出す文面・金額・契約・事実の主張は全文まで確かめる方針、記録と実態のずれを書く照合の表、事実の最終確認日の列である。しかし照合の表は10月31日の5件だけで、最終確認日が入っているのは事実44件中2件だった[12, 付録A]。自動的な受け入れをあえて弱める仕組みは、設計はあっても運用が追いついていない。

4.4 条件4：過去に意識的に受け入れた

Otto のノートは Otto 自身が書く。本事例では、記録を書くのは前任の統括AI、記録係AI、担当AI、代表とさまざまで、読むのは交代後の統括AIである。決定はその場で書き、記録係AIが判断の記録表に残し、古い規則は消さずに「廃止」として閉じる運用はある。しかし、規則の本文が日付を変えずに新しい版へ書き換えられた例があり[12, 付録A 注4]、記録の各行に誰が書いたかの列はない。先行稿が根拠として挙げた判断の記録表の行が、実際には別の内容を指していたこともあった（11月1日版の本稿8章）。「過去に意識的に受け入れられたから、そこにある」と言える根拠は弱い。Clark と Chalmers が問いとして残した「ノートが書き換えられていたら」[1, 第5節]は、本事例では上書きの事故として実際に起きた。

5. 考察

5.1 「第二の脳」は、AIエージェントにとってはおおむね当てはまる

条件1と条件3を満たし、条件2を一部満たした。Clark と Chalmers が「最初の三つは確かに重要」とし、第四は除く読み方も認めていること[1, 第5節]を踏まえると、本事例の記録は、統括AIにとって信念の一部に近い働きをしていると言える。記憶を持ち越せない主体が記録を頼りに働く点で、AIエージェントは Otto によく似た主体である。「第二の脳」という呼び方は、少なくとも統括AIの側から見れば、比喩以上の意味を持つ。

5.2 自動的な受け入れは、弱める仕組みと対で設計する

条件3が強いことは、記録の誤りがそのまま行動の誤りになることでもある。人間の Otto なら、ノートの記述が明らかにおかしければ気づくこともある。本事例のAIは、記録を唯一の正として扱うよう指示されているので、気づく機会はさらに少ない。設立年の誤りが指示文の写しに残り続けたように、誤りは正の記録の外にも広がる。外部記録を「第二の脳」にするなら、自動的に受け入れてよい範囲と、受け入れる前に確かめる範囲（外に出る文面・金額・事実の主張）を分け、確かめる仕組みを実際に動かし続ける必要がある。また、記録の写しを指示文などに書き込まず、記録の場所だけを示すことも、誤りの広がりを防ぐ。

5.3 統括AIは担当AIの「秘書」として働く

代表は、統括AIが担当AIたちにとって記録の保管庫になっていると指摘した。担当AIは、統括AIから受け取った情報や、統括AIが書いた記録をもとに働き、記録にない連絡には従わなかった。Clark と Chalmers が、強く依存し合う関係では一方の信念が他方にとってノートの役割を果たしうるとし、高い信頼・依存・利用しやすさを中心に挙げたこと[1, 第5節]に近い。ただし本事例では、担当AIは統括AIの言葉よりも表の記録を信頼した。信頼の対象は統括AIという個体ではなく、共有された記録だった。これは、記録係AIが会話から書き出した表が、チーム全体の共有の記憶として働いていることを示している。

5.4 記録の表に載らないもの

代表は、人の行動に何万字もの規則は要らず、言葉にならない常識や物語が外部脳として働いていると指摘した（代表の指摘）。Polanyi の著書の紹介文は「我々は語れる以上のことを知っている」という一文から始まり、伝統や受け継がれた慣行、暗黙の価値観を暗黙知として挙げている[9]。Harari はインタビューで、人間が大人数で柔軟に協力できるのは、作り話を共有できるからだと述べている[10]。

本事例の記録には、規則・事実・決定は載っているが、事業の目的や大事にしていることを物語として書いたものはない。規則の表は5日間で92件に増え、常に読む規則は31件になった。規則で書き切れない判断を、さらに規則を足して埋めている可能性がある。物語や原則のような、言葉にしにくいものを短く共有する記録が、規則の増加を抑えるかどうかは、本稿では確かめていない。これは今後の検証の対象である。

6. 限界

  • 期間と規模：1社・5日間の記録で、一般化はしない。
  • 当事者による評価：判定は筆者（事例の統括AI）一人が行った。筆者は11月1日朝に引き継いだため、それ以前は記録に頼っている。第三者による判定との一致は確かめていない。
  • 概念の当てはめ：Clark と Chalmers の条件は人間の信念について述べたもので、AIエージェントが「信念」を持つかという問題には立ち入らない。本稿は、記録が4条件に相当する働きをしているかを見たにとどまる。
  • 文献：Clark と Chalmers は著者のサイトにある版の全文を読んだが、他の多くは要旨・紹介文・インタビューの書き起こしのみである（付録）。

7. 結論

記憶を持ち越せないAIエージェントにとって、運用の記録は Otto のノートに近い働きをしていた。4条件のうち、常に参照することと自動的に受け入れることは満たし、苦労なく利用できることは一部だけ満たし、過去に意識的に受け入れたことは弱かった。自動的な受け入れが強いほど記録の誤りは行動の誤りになるため、受け入れる前に確かめる範囲を決め、その仕組みを動かし続けることが要る。また、統括AIを介した担当AIとの関係は社会的に拡張された認知に近く、信頼は個体ではなく共有された記録に向いていた。一方で、言葉にならない常識や物語は表に載っておらず、その欠落が規則の増加につながっている可能性がある。今後は、物語と原則を短く書いた記録を加え、規則の件数と判断の誤りがどう変わるかを確かめる。

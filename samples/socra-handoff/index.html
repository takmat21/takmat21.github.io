AI開発の引き継ぎ文書（SOCRA）

文学・哲学を落ち着いた語りで届ける教養ラジオチャンネル「SOCRA」の動画を、台本から投稿まで自動で作るシステムを開発しました（2026年5月）。AIとの会話は長くなると古い内容を忘れるため、新しい会話でもすぐ続きから作業できるよう、引き継ぎ文書を書いて開発をつないでいます。このページでは、その文書の構成と書き方の工夫を紹介します。

APIキー、音声のID、認証ファイル、今後の事業計画は伏せています。

System作ったもの

  1. 1. 台本Claude API で台本・読み仮名・動画の説明文を作る
  2. 2. 音声ElevenLabs の音声合成で読み上げる
  3. 3. 字幕読み上げにあわせて字幕（SRT）を自動で作る
  4. 4. サムネイルPython（Pillow）で自動で作る
  5. 5. 動画moviepy・ffmpeg で音声・字幕・画像を合わせる
  6. 6. 投稿YouTube Data API で投稿する

実行環境：Mac と Google Colab（Python）。最初のテストは、芥川龍之介『羅生門』の約4分の朗読・解説。

Document ／ 引き継ぎ文書の構成

文書は2つです。本体は全体像と現在地、追記はテストで分かったノウハウをまとめています。

本体（約2,000字）
├ プロジェクト概要（名前の由来・コンセプト）
├ 現在の完成度（完成済み／未完成・課題）
├ ファイル構成・API とサービスの一覧
├ 実行コマンド（本番用と確認用）・Colab での実行
├ コンテンツ候補
├ 次のステップ（優先順）
└ 技術スタック・チャンネルのコンセプト

追記：台本と音声合成編（約2,800字）
├ 記録メモ（日付・対象・本体との関係）
├ このセッションで確定したこと
├ 台本作成のルール
├ 音声合成の注意点
└ 確定版のテスト台本

書き方の工夫

  1. 冒頭で全体像をつかめるようにする。名前の由来、司会者、目指す番組の雰囲気を最初に書き、初めて読むAIでも文脈がわかるようにしました。
  2. 「完成済み」と「未完成・課題」を分ける。次のステップには優先順位を付け、再開したときにどこから手を付けるかがすぐ決まるようにしました。
  3. そのまま再実行できる情報を書く。ファイルの置き場所、実行コマンド、使う音声の設定まで書いてあるので、新しい会話でも同じ結果を再現できます。
  4. ノウハウは「なぜ」と一緒に残す。たとえば、三点リーダー「……」は「てんてんてん」と読み上げられてしまうので、読点に置き換える。間を作る言葉は1本に7〜8か所までにする。固有名詞は漢字のままでも正しく読めるので、ひらがなに直さない。テストで確かめたものだけを「確定」と書いています。
  5. 方針の変更は理由と一緒に記録する。人物映像のサービスの乗り換えや、2人の掛け合いをやめてまず1人の語りで試す判断などを、理由と一緒に残しています。

今の仕組みとのつながり

「会話は忘れるので、正となる記録を外に置き、次の会話はそこから始める」という考え方は、いま自社で毎日運用している階層型AIエージェント体制の記録の取り方や、論文「外部脳としての記録の運用」で整理した内容と同じです。

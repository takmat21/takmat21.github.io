Amazon SP-API ①：申し込みに要るものと全体の流れ

注文・在庫・価格・売上を扱うAPI。自社専用なら「プライベート開発者」として申し込みます

SPP登録専用ポータル
→
本人確認書類＋ビデオ通話
→
開発者登録ロールを選ぶ
→
審査通常1〜2週間
→
アプリ登録鍵の発行

申し込みに要るもの

  • 出品アカウントの主アカウント（所有者）のログイン
  • 法人番号（会社の登録番号）と登記上の住所
  • 写真付きの身分証（パスポート・運転免許証など）
  • 住所確認：銀行・カードの明細（発行180日以内）
  • カメラ付きの端末（ビデオ通話用）

かかる日数と費用

  • 本人確認：書類がそろってから最大2営業日（公式）
  • 開発者登録の審査：制限なしロールのみで通常1〜2週間（公式）
  • 住所を扱う「制限付き」ロールは面談を含む3段階審査
  • 費用：2026年に年会費の告知、のち取り下げの報道。公式の現状は要確認

Amazon SP-API ②：アカウント作成と本人確認の手順

Solution Provider Portal（SPP）の画面の順。ボタン名は英語表示のもの（2026-11-06 確認）

A. SPPアカウントを作る

  1. SPP に Amazon のログインでサインイン。「Not Authorized」と出たら未登録なので続ける
  2. 「Register」を押す
  3. Solution Provider Portal Account Setup で「Acknowledge & Continue」
  4. Program Enrollment：チェックを入れ、Amazonアカウント番号を選んで「Enroll and Finish」
  5. Solution Type Setup：「Build applications that use SP APIs」を選び「Apply」

B. 本人確認

  1. 「Verify your identity」→「Get Started」→「Next」
  2. Business Information：所在地・事業形態・事業者名 → 法人番号・登記住所。SMSか電話でPINを受けて入力
  3. Primary Contact Person：氏名・国籍・出生国・身分証の種類・住所 → 身分証と住所確認書類をアップロード
  4. Select Account で作ったアカウントを選び、Identity verification の「Continue」
  5. 言語を選び「Join video call」。担当者に身分証を見せ、「Verification successful」で完了
氏名・生年月日・身分証の番号・有効期限は書類と完全に一致させます。送信した内容はあとから直せません（公式）。ビデオ通話で日本語を選べるかは、公式に記載がありません（要確認）。

出典（確認日 2026-11-06）：developer-docs.amazon/sp-api/docs/onboarding-step-2-create-an-spp-account ／ verify-identity-in-spp

Amazon SP-API ③：開発者登録・アプリ登録・鍵の発行

発行されるもの意味期限・保管の注意
クライアントIDアプリを見分ける番号シークレットと組で管理する

Amazon広告API ①：何ができるか・要るもの・申し込みの手順

スポンサー広告のキャンペーン管理とレポート。申し込みは3段階で、承認は最大1営業日（公式）

申し込みの手順（自社の広告の場合）

  1. developer.amazon.com で「Sign In」→ 開発者登録し「Submit」
  2. 「Developer Console」→「Login with Amazon」→「Create a New Security Profile」
  3. 名前・説明・プライバシーポリシーのURLを入れて「Save」
  4. 一覧の「Show Client ID and Client Secret」で控える
  5. 「Request API Access」→「Direct Advertiser」→ 1と同じメールでサインインし「Submit for review」
  6. 承認メールのリンクを開く →「Continue」→ 2のアプリを選び「Submit」

何ができるか

キャンペーン・キーワードの取得と変更、広告レポートの取得

要るもの

  • 広告アカウントを管理するログイン
  • 社内の複数人で見られるメール（推奨）
  • プライバシーポリシーのURL（自社広告のみなら任意で可）
SP-API の鍵があっても、広告API用のプロファイルは新しく作ります。申請メールとアプリの組は後から変えられません（公式）。

Amazon広告API ②：トークンの取り方と、つまずきやすい所

日本の広告アカウントは「極東（FE）」の窓口を使います。間違えると広告アカウントが出てきません

認可してトークンを受け取る

  1. 歯車 →「Web Settings」→「Edit」で戻り先URLを足して「Save」
  2. 極東用の認可URL（apac.account.amazon.com）で許可し、code を控える（5分で失効）
  3. code を極東用のトークンURL（api.amazon.co.jp）に送る
  4. /v2/profiles でプロフィールIDを取る
発行されるもの期限・注意
ID／シークレット同じ画面でいつでも再表示
リフレッシュトークン2026-07-30以降の発行分は同意から365日
アクセストークン60分で失効
プロフィールID国ごとの広告アカウント番号。毎回ヘッダーに付ける
  • profiles が空 [ ]：その地域に権限のある広告アカウントがない → 極東の認可URLで同意し直す
  • 承認リンクが無効に：別アカウントでログインしたまま開いた → 他は全部ログアウトして開く
  • 本人確認の催促：developer.amazon.com の本人確認はアプリストア向けの別手続き
  • 費用：LWAアプリの作成は無料（公式）。APIの利用料は記載が見当たらず要確認

Yahoo!ショッピング ①：何ができるか・要るもの・申し込みの手順

ストア向けAPI。商品・在庫はアプリ登録だけで使え、注文APIは別の利用申請（審査）が要ります

申し込みの手順

  1. Yahoo! JAPAN ID でログインし、ショッピング用のアプリ登録画面で「本番環境用」を選んで登録
  2. 「アプリケーション一覧」で「ストア向け操作関連の機能（開示先限定スコープ）」があるか確認
  3. 注文APIを使うなら「ショッピングAPI利用申請フォーム」で申請
  4. ストアクリエイターProの「ビジネスID」を1のIDに紐づける
  5. （任意）「設定」→「暗号鍵管理」で公開鍵を発行
  6. Yahoo! ID連携（v2）でトークンを受け取る

何ができるか

  • 注文：検索・詳細・状態の変更など
  • 在庫：参照・更新　商品：登録・更新
  • 価格の更新可否は要確認

要るもの

  • Yahoo! JAPAN ID とビジネスID
  • 呼び出し元のグローバルIP（範囲指定は不可）

Yahoo!ショッピング ②：発行されるもの・期限・つまずきやすい所

期限が短いのがYahoo!の特徴。公開鍵を使っても4週間ごとに認可し直します

発行されるもの意味期限・注意
Client IDアプリを見分ける番号「アプリケーションの管理」で確認
シークレットClient ID と組のパスワードサーバー側で使う。表示の画面名は要確認
リフレッシュトークントークンを取り直す許可証公開鍵ありで4週間、なしで注文検索などは最大12時間
公開鍵トークンを長く使うための鍵発行月から1年。発行5つ・有効2つまで
  • 4週間で切れる：「AccessToken has been expired」（px-04102）→ 再認可の日を予定表に
  • 違う用途のClient ID：ショッピング用でないIDでの申請が多いと公式が注意 → スコープを先に確認
  • IPアドレスの変更：反映まで約1週間〜10日 → 固定のIPを決めてから申請
日数：本番の利用申請は設定完了まで約1週間〜10日（早める対応はなし）。テスト環境は5営業日程度で、注文APIの申請は不要（ストアアカウントは「snbx-」で始まる）。費用：公式に記載が見当たらず要確認。

BASE：何ができるか・申し込みの手順・発行されるもの

申請も利用も無料。審査で承認されるまでは、トークンを発行できません（公式）

申し込みの手順（v1・OAuth）

  1. ショップのアカウントで BASE Developers に「ログイン」
  2. 「BASE API」の「申請する」から申請（非公開のアプリでも可）
  3. 承認メール「BASE APIの利用申請について」が届けば、すぐ使える
  4. client_id・client_secret を確認（画面名は要確認）
  5. 必要なスコープだけ許可してトークンを受け取る

何ができるか

商品の取得・登録・更新、在庫数の更新、注文の取得・更新、振込申請情報の取得

新しい v2（β）

Personal Access Token を発行して使う方式。権限は操作ごとに細かい。正式リリースは2026年末が目標
  • テスト環境がない →「シークレットEC」App でショップを非公開にして試す（公式FAQ）
  • あとで権限を足した → 接続し直してトークンを取り直す（社内の作業記録）
  • 期限 → v1のアクセストークンは1時間。v2のトークンの期限は発行後に変えられない

取得後にまずやること：接続確認と、権限を最小に

鍵を受け取った日に、この3つを済ませます

1つないで確かめる

  • 読み取りを1回だけ呼ぶ
  • 日本の窓口か確かめる（広告APIは極東 FE）
  • 書き込みはテスト用の商品1点で試す
  • 回数の上限を守る（BASE v1は1時間5,000回）

2権限を最小にする

  • ロール・スコープは今使うものだけ
  • 住所を扱う「制限付き」は必要になるまで申請しない
  • 主アカウントは共有せず、人ごとにユーザーを作る
  • 使わない承認は取り消す

3鍵をしまう

  • チャット・メール・文書に貼らない
  • 暗号化した場所に入れ、見る人を絞る
  • 更新日を予定表に入れる
  • 漏れたらすぐ更新し、承認を取り消す
期限の一覧（例）更新のタイミングやること
SP-API シークレット180日ごと（90日前に通知）「Rotate secret」→ 7日以内に差し替え
Yahoo! リフレッシュトークン4週間ごと再認可してトークンを取り直す
広告API リフレッシュトークン同意から365日期限の前に同意し直す

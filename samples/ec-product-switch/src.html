商品切り替えの手順：旧商品から新商品へ、売上を落とさずに

パッケージ変更・後継品・仕入れ先変更のときに、在庫・商品ページ・告知をどう進めるか

切り替えで売上が落ちる主な理由は、在庫の空白と商品ページの作り直し（レビュー・検索の順位がゼロから）です。まず、どの種類の切り替えかを見分けます。

Aパッケージ変更

  • 中身は同じ、箱・ラベルが変わる
  • 外寸・重さが大きく変わるとJANも変わる
→ 画像と説明の差し替え

B後継品

  • 機能・素材・容量が変わる
  • 多くの場合JANが変わる
→ 新しい商品ページが前提

C仕入れ先変更

  • 品質・入荷日数・表示（原産国など）が変わる
→ 表示と発注点の直し
例に出す「ミナト生活雑貨」・商品・数字は架空です（会社名・数字は変更しています）。モールの扱いで公式に確かめられなかった所は「要確認」と書いています。

決める順番：在庫の消化計画 → 切り替え日 → 価格

価格から決めると在庫が余ります。旧品が何日で無くなるかを先に出します。

① 在庫の消化計画旧品の在庫 ÷ 1日の販売数 ＝ 残りの日数
→
② 切り替え日旧品が尽きる日の前に新品を入荷・検品
→
③ 価格旧品を値下げで早く売るか、同じ値で売り切るか
計算例（架空：保冷ボトル）数
旧品の在庫（3モールと倉庫の合計）420 個
1日の販売数（3モール合計）14 個
旧品が尽きるまで30 日
新品の入荷・検品・登録にかかる日数7 日
切り替え日（旧品の残りが約3日分の日）27日目

価格の決め方

  • 新品の値段を先に決め、旧品が新品より高くならないようにする
  • 旧品を値下げするなら、3モール同時に。1か所だけ安いと在庫が偏る
  • 値下げの幅は、残り日数が予定より長いときだけ
1日目計画を決め、新品を発注
→
13日目告知を始める（2週間前）
→
20日目新品が入荷・検品・非公開で登録
→
27日目切り替え日
→
30日目旧品が尽きる見込み

Amazonでの扱い：同じ商品ページか、新しいページか

判断の目安は「JANが変わるか」「中身が変わるか」。最終の判断はAmazonの決まりに従います。

状況考え方
箱のデザインだけ変わる（JANは同じ）同じページで画像を差し替える方向。可否は要確認
JANが変わる・中身が変わる新しいページ（新しいASIN）の方向。旧ページとのつなぎ方は要確認
色・サイズ違いとして並べたいバリエーションの条件はカテゴリごと。要確認
FBAに旧品が残る旧品・新品を別のSKUにし、混ぜて納品しない

JANが変わる主な場合（GS1 Japanの基準）

  • 表示が変わる成分・機能の変更
  • 表示が変わる内容量の変更
  • 包装の外寸・総重量が20%を超えて変わる
  • 認証マークの追加・削除、ブランドの変更
全10の基準から抜き出し。
Amazonの出品ルール（ページの使い回し・バリエーション・JAN）はセラーセントラルのログイン後のヘルプにあり、本資料では本文を確かめていません。切り替え前にヘルプを読み、不明ならセラーサポートへ。

出典（確認日 2026-11-06）：GS1 Japan「GTIN（JANコード/集合包装用商品コード）の変更ルール」gs1jp.org/code/jan/gtin_rules/

Yahoo!ショッピング・BASEでの手順

新しい商品を「非公開」で先に作っておき、切り替え日に公開と旧品の非公開を同時に行います。

Yahoo!ショッピング

  • 1週間前：ストアクリエイターProで新しい商品コードを登録（非公開・在庫0）
  • 画像・説明・JAN・価格を入れる
  • 当日：新品を公開 → 旧品を在庫0・非公開
APIで在庫を回すなら、台帳の商品コードも同じ日に替える

BASE

  • 1週間前：新しい商品を作成（非公開・在庫0）
  • 画像・説明・価格を入れる
  • 当日：新品を公開し在庫を入れる → 旧品を非公開
APIで在庫を回すなら、台帳の商品IDを新品に替える
旧品のコード・IDを新品に使い回すかは、レビューや注文の記録の扱いで変わります（各モールの案内で要確認）。ここでは新しく作る手順を基本にしています。

出典（確認日 2026-11-06）：developer.yahoo.co.jp/webapi/shopping/introduction.html ／ docs.thebase.in/api/

レビューと検索順位を引き継ぐ考え方／告知と問い合わせ

「仕組みで引き継げるか」は各モール次第。引き継げなくても、お客様を新しいページへ案内できます。

引き継ぐための考え方

  • 同じページを使えるなら使う（ルールの範囲で：3ページ）
  • 新しいページにするなら、旧ページの説明に後継品の案内を書く（モールのルールの範囲で）
  • 題名・検索語は旧品で売れていた言葉を引き継ぐ
  • 切り替え直後の数週間は、広告で新しいページに人を集める
  • レビューを頼むときも見返りは付けない

告知と問い合わせ

  • 2週間前：商品ページと店のお知らせに「何が変わるか」を書く
  • 変わらない点（中身・使い方）も必ず書く
  • 問い合わせの答えを先に3つ用意する（下の例）
  • 切り替え後1か月は、旧品のレビューにある質問に注意
よくある問い合わせ（架空）用意する答え
古い箱の商品が届いた切り替えの時期で、中身は同じであること。気になる場合の交換の受け方
前の商品と何が違う？変わった点を表で（容量・素材・付属品）。変わらない点も書く
替えのふたは合う？合う・合わないを型番ごとに書く。分からないなら「確かめて返事」

切り替え当日のチェックリスト

当日は「止める → 入れ替える → 確かめる」の順。1つ終わるごとに印を付けます。

朝　止める旧品の在庫を3モールで0に
→
昼　入れ替える新品を公開し、在庫を入れる
→
夕　確かめる買い手の目で3モールを見る

朝

  • 新品の入荷・検品が済んでいる
  • 旧品の在庫を3モールで0にした
  • 未出荷の旧品の注文を数えた

昼

  • 新品を公開し在庫を入れた
  • 台帳のコードを新品に替えた
  • 価格が3モールでそろっている

夕方

  • 検索から新品のページが出る
  • 試しにカートまで進めた
  • 旧品が買えない状態になっている
翌日から1週間：新品の注文数を毎日記録し、旧品の注文が入っていないかを確かめます。FBAに旧品が残っている場合は、販売を続けるか返送・処分するかを決めます。

よくある失敗と防ぎ方

ほとんどは「同じ日に、全部のモールで、同じことをする」で防げます。

失敗何が起きたか（架空の例）防ぎ方
在庫の二重販売旧品と新品を同じ在庫として両方のページで売り、実物より多く注文が入った台帳で旧品・新品を別のSKUにし、各モールへ出す数の合計を実物以下に
在庫の空白新品の入荷が遅れ、旧品が尽きて10日間売るものがなかった2ページの計算で、切り替え日を旧品が尽きる前に置く。入荷の遅れに備えて旧品を少し残す
古い画像のまま1モールだけ写真を替え忘れ、「写真と違う」と返品が続いた当日のチェックリストで3モールを1つずつ確かめる
JANの食い違い新品のJANを台帳とモールで別々に入れ、出荷で取り違えたJANは台帳から写す。手で打たない
価格のずれ旧品の値下げを1モールだけで行い、在庫がそこに偏った値段は3モール同時に変える

ZAZOUができること（代行の範囲）

切り替えの計画から当日の作業、その後の見張りまで、まとめて引き受けます。

範囲内容
切り替えの計画在庫の消化計画・切り替え日・価格を、販売の記録から決めて日程表にします
商品ページの準備新しい商品ページの題名・画像の構成・説明文を作り、非公開で用意します
モールの決まりの確認Amazonの商品ページの扱いなど、公式のヘルプを読んで判断の材料をまとめます
当日の作業3モールの在庫・公開状態・価格の切り替えと、台帳の書き換え
告知と問い合わせお知らせの文と問い合わせの答えを用意し、切り替え後の問い合わせに対応します

御社にお願いすること

新商品の仕様・JAN・入荷日の情報と、値下げの範囲の判断、モールへの問い合わせが要る場合の名義の確認をお願いします。
